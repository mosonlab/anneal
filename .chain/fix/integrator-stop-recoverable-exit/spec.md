Merge tail: a base-drift stop whose question was deferred always has an exit after recovery, on resume and after a failed integrator run

Goal: a chain that reached merge authorization is never left with an integrator task that refuses every retry because its stop question was deferred and the one intent that could bypass the stop has already been spent.

Background: for a canonical integrator step, a `base-drift` stop defers its operator question (`packages/db/src/merge-integrator-db.ts`, `questionDeferred` around `:722-725`) and hands the case to automatic base-drift recovery. The only path that may open a new integrator Run while that stop remains in history is the `integrator-authorized` intent readiness raises when it re-authorizes (`packages/db/src/run-open.ts:990-1010`, `humanReauthorization`). That intent is raised once, at authorization time. Two production shapes on 2026-09-07 left three chains with no exit: (1) `dc676a74` and `d018602b` — readiness re-authorized at 01:30Z and 01:44Z while the chain was held at the integrator's layer, the Run birth was refused by the hold, `chain/resume` does not replay the intent, and the recovery aggregate stayed `repairing`; (2) `e8b2cb80` — recovery succeeded, the integrator Run opened and then failed on an external error (GitHub App installation-token mint during a GitHub outage window) and never released the merge Lease; `POST /tasks/:id/retry` and `/start` answer `Merge integrator stopped on base-drift; answer the stop question before starting another run`, and there is no question card to answer. Operators delivered all three by hand (`records/anneal/STATE-oss-compare-wave1-20260906.md`, 02:47Z-02:56Z) and stole the Lease with `merge-lease.sh steal --human`.

Changes:
1. A base-drift recovery whose readiness authorization lands while the chain is held records the pending `integrator-authorized` intent on the recovery aggregate instead of dropping it; `chain/resume` replays it for the held layer exactly once, opening the integrator Run under the same admission `POST /tasks/:id/start` uses. The aggregate leaves `repairing` only when that Run is born.
2. An integrator Run that fails with an external failure class after a successful recovery (transport, credential mint, API 5xx) does not leave the stop unanswerable: the failure re-queues the integrator through the ordinary recovery path (a fresh `integrator-authorized` intent bound to the same authorization while the authorized base is still main, otherwise a new base-drift recovery), bounded by the existing recovery attempt ceiling. A deterministic refusal (forbidden, unprocessable, not-found) still stops and, for a canonical step, opens the deferred question so an operator has something to answer.
3. When the integrator Run ends for any reason without completing its merge, the merge Lease it was handed is released by the same completion path that records the failure; the release is recorded as a `MergeLeaseEvent`.
4. `docs/operator-api.md` states the three rules where the merge tail, `chain/resume`, and the merge Lease are described. Only sentences that become inaccurate change.

Out of scope: the readiness authorization precondition on executor liveness (separate card); merge-train; the semantic-verdict reuse in recovery (separate card); the lease protocol's timeouts and the 45-minute steal threshold.

Constraints: one owner for each intent replay (the aggregate), no second question surface for canonical steps beyond the one that already exists for deterministic refusals, every replay and every lease release leaves a TaskActivity; dbtests run only on the merge gate.

Acceptance: `npm run test -w @anneal/api` and `-w @anneal/db` green. dbtests cover: authorization landing on a held chain followed by resume opens exactly one integrator Run and moves the aggregate out of `repairing`; a second resume opens nothing; an integrator Run failing with a transport class after recovery re-queues without operator input and the Lease is released with an event row; a deterministic refusal on a canonical step opens the deferred question. Handbook updated in the same diff.

Route: implementation=senior-dev-opus-high - three interacting state machines (recovery aggregate, chain hold, merge Lease) and the failure (a chain with no exit) cannot be witnessed by the acceptance suite alone
