Merge gate: an infrastructure failure inside the gate reports GATE NOT RUN, never a commit FAIL

Goal: a gate run that cannot judge the commit because the host (Docker daemon, cleanup) failed exits with the no-verdict code, so the dispatcher tries the fallback worker instead of recording a judgement nothing made.

Background: `scripts/merge-gate.sh` documents (header lines 11-26) that exit 1 is the only code meaning "judged and did not pass" and that a run which judged nothing must not hand its caller a FAIL. The implementation does not honour that for host failures: `die()` (`merge-gate.sh:208-212`) always exits 1, and the Docker preflight (`:979-982`) calls it when the daemon is unreachable. `scripts/gate-worker/verdict.sh:52-56` then prints `MERGE GATE: FAIL (docker preflight)`, `run-gate.sh:344-357` and `remote-gate.sh:248-262` pass it through, and `gate-dispatch.sh:453-457` treats exit 1 as a judgement (`gate_verdict_is_judgement`, `lib.sh:315-319`) and returns without trying the fallback worker. `verdict.sh:66-70` likewise turns a pure host cleanup failure (`docker rm -f` failing, lock release refused) into FAIL, while the deliberate `--keep-postgres` case (`:72-77`) correctly uses NOT AUTHORITATIVE (3). Two adjacent defects in the same file: the worktree lock (`merge-gate.sh:255-278`) does `mkdir` then writes the pid, so a competing gate that reads an empty pid file removes and recreates the directory and both gates proceed (the empty-holder window `lib.sh:118-132` explains the `ln` shape exists to remove); the correct primitive `gate_slot_try`/`gate_slot_release` is already sourced and used for the cache writer lock (`:331-341`). And `scripts/merge-gate-profile.mjs:5-13` lists `docs/runbooks/gate-worker.md` as a docs-only fast document although `scripts/gate-worker/gate-dispatch.test.mjs:1262-1287` and `gate-worker.test.mjs` read that file as assertion input, so a commit that only edits the runbook passes the docs-only profile and the breakage surfaces in the next full gate of an unrelated commit.

Changes:
1. Add a `die_no_verdict()` helper to `scripts/merge-gate.sh` that records the reason and exits with the gate's existing no-verdict code (76, the same code used for an externally stopped step), and use it for the Docker preflight failures at `:979-982` (docker binary missing, daemon unreachable). Do not change `die()` for precondition failures that are about the commit or the invocation (bad `--expect-head`, dirty tree, unresolvable master oid): those stay exit 1.
2. In `scripts/gate-worker/verdict.sh`, classify a host cleanup failure (container removal failed, lock release refused) after all steps passed as NOT AUTHORITATIVE (3) rather than FAIL (1); a cleanup failure after a step failed stays FAIL. The last output line must still be one of the documented `MERGE GATE:` / `GATE NOT RUN:` forms.
3. Replace the mkdir-then-write-pid worktree lock (`acquire_lock`/`release_lock`, `merge-gate.sh:255-278`, `:238-248`) with the atomic `gate_slot_try`/`gate_slot_release` primitive from `lib.sh`, rooted at the worktree, keeping the current semantics: a live holder is an immediate FAIL naming the holder's pid, never a wait.
4. Remove `docs/runbooks/gate-worker.md` from the docs-only allowlist in `scripts/merge-gate-profile.mjs`, and add a guard test in `scripts/merge-gate-profile.test.mjs` asserting that no allowlisted document is referenced by path from any `scripts/**/*.test.mjs` or `packages/**/*.test.*` file.
5. Update the exit-code table in `docs/runbooks/gate-worker.md` and the fixtures in `scripts/gate-worker/gate-worker.test.mjs` / `gate-dispatch.test.mjs` so they state and test that a Docker preflight failure yields GATE NOT RUN (76) and that the dispatcher proceeds to the fallback worker on it.

Out of scope: gate speed, lane widths, the build snapshot cache, the separate `npm ci` per gate, the throwaway PostgreSQL reaper (A-04), the worker slot-wait timeout (A-05), `run-gate.sh` host-share derivation, `scripts/merge-train.mjs`, and anything under `packages/`.

Constraints: exit codes 0/1/3/76/130/143 keep their documented meanings; no new exit code. The no-verdict path must still delete the throwaway PostgreSQL container and release the worktree lock. The change to merge-gate.sh is itself gated by the merge gate; it must not depend on the fix to pass.

Acceptance: `node --test scripts/merge-gate-parallel.test.mjs scripts/merge-gate-profile.test.mjs scripts/gate-worker/gate-worker.test.mjs scripts/gate-worker/gate-dispatch.test.mjs` is green; a fixture drives `merge-gate.sh` with a stubbed `docker` that fails `docker info` and asserts exit 76 and a last line starting `GATE NOT RUN:`; a fixture asserts `gate_verdict_is_judgement 76` is false; a fixture asserts two concurrent `acquire_lock` calls on one root leave exactly one holder; `docs/runbooks/gate-worker.md` is absent from `FAST_DOCUMENTS` and the new allowlist guard test passes; the runbook exit-code table names 76 for Docker preflight.
