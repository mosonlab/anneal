Gate worker: orphaned gate databases are reaped, a slot wait ends as GATE NOT RUN, and host share is its own setting

Goal: a gate worker never accumulates orphaned PostgreSQL containers, a gate waiting for a worker slot gives up with the no-verdict code instead of hanging the ssh session, and the fraction of the host a gate may use is an explicit setting rather than a side effect of worker capacity.

Background: (1) `scripts/merge-gate.sh` starts a detached PostgreSQL container (`:1113-1125`, name prefix `agentos-merge-gate-`, tmpfs up to 3072m) and relies on the EXIT trap in `scripts/gate-worker/verdict.sh:16-35` to remove it; SIGKILL and OOM skip the trap, `--rm` does not stop a running container, and no other code path removes them (grep for the prefix hits only `merge-gate.sh:199`). Two containers that had been running for two weeks were removed by hand on 2026-09-06. testcontainers (Ryuk) and pg_tmp both reap by owner liveness. (2) `packages/runner/runtime-tools/gate-worker/run-gate.sh:217-233` waits for a worker execution slot with no timeout; `gate-dispatch.sh`'s outer `--timeout-minutes` cannot interrupt an attempt already inside `run_remote` (`gate-dispatch.sh:365-386,526-561`), so a configuration drift between the dispatcher's slot count (`:176-182`, hardcoded 2 for primary) and the worker's `worker-capacity` file shows up as a silent ssh hang. (3) `run-gate.sh:189-209` passes the worker capacity straight through as the gate's host share, and `scripts/gate-worker/host-sizing.sh:7-22` divides the machine's CPU count by it. When the primary worker is `gate-self` (gate on the same host as 16 runners) with capacity 1, a gate sizes itself to the whole machine, contradicting the sizing comment that a shared runner host should take half. The invariant that N concurrent gates add up to one machine must survive.

Changes:
1. Add a reaper step at the start of `run-gate.sh` (worker side) that lists containers with the gate name prefix and removes only those whose owning gate is provably dead: the container label carries the gate's pid and worktree path (add the label at creation in `merge-gate.sh`), and a container is removed only when that pid is not alive and its worktree directory no longer exists. Containers whose owner is alive or unknown are left alone and logged.
2. Bound the slot wait in `run-gate.sh:217-233` with a configurable timeout (default 20 minutes); on expiry print `GATE NOT RUN: worker slot wait exceeded <n> minutes` and exit with the no-verdict code (76) so `gate-dispatch.sh` proceeds to the fallback worker (it already treats 76 as not a judgement).
3. Introduce an explicit worker-side setting for host share (a `host-share` file next to `worker-capacity`, integer ≥ 1) read by `run-gate.sh` and passed to `merge-gate.sh`; default it to the worker capacity so existing workers are unchanged, and document in `docs/runbooks/gate-worker.md` that a worker sharing its host with runners should set it to at least 2. `provision.sh` writes the default file.
4. Add a dispatcher-side sanity log: when `gate-dispatch.sh` selects the primary worker, read the worker's `worker-capacity` over the existing ssh channel and log a warning if it differs from the dispatcher's configured slot count (no behaviour change).

Out of scope: `merge-gate.sh` exit-code changes for Docker preflight (previous chain), lane-width derivation inside `merge-gate.sh`, `scripts/merge-train.mjs`, mirror push and ref retention (A-09), the bench scripts.

Constraints: the reaper must never remove a container it cannot attribute; every removal is logged with the dead pid and worktree. The host-share default preserves current sizing exactly. Exit codes keep their documented meanings. Runbook exit-code table updated for the slot-wait case.

Acceptance: `node --test scripts/gate-worker/gate-worker.test.mjs scripts/gate-worker/gate-dispatch.test.mjs scripts/merge-gate-parallel.test.mjs` green; fixtures cover: a container labelled with a dead pid and missing worktree is removed, one with a live pid is kept, one without labels is kept and logged; a stubbed slot wait past the timeout exits 76 with the `GATE NOT RUN:` line; `host-sizing.sh` with `host-share=2` on a 16-CPU host yields half the lanes; the capacity/slot mismatch warning appears in the dispatcher log fixture.

Route: implementation=senior-dev-opus-high - the reaper is a destructive host operation on the gate worker and the slot/share settings change how concurrent gates divide a machine; fixtures cannot witness the live-container race
