Runner/API: failures in the runner's own phases (PROVISION, DELIVER, COMPLETE) are retried by phase and by a deterministic-refusal veto, not by matching transient error text; a failed branch push is re-pushed without re-running the agent

Goal: whether a failed Run is retried and refunded no longer depends on the failure text matching an ever-growing list of transient phrases. In the phases that are the runner's plumbing (clone, workspace, push, PR, completion) the default is "transient, retry, refund"; only a short deterministic-refusal veto (auth, 401/403, permission denied, NO_CHANGES_PRODUCED, BUDGET_EXCEEDED) makes such a failure final. A DELIVER failure re-pushes the commit the agent already produced instead of spending a new agent session.

Background: on 2026-09-07 13:05-13:44Z chain d3520ecf step 2 (luna-max, vm-runner-10, 40 minutes) finished its implementation (commit `50f8cf92`, tests green); the runner's branch push failed with `git failed (128): fatal: unable to access 'https://github.com/mosonlab/agentos.git/': gnutls_handshake() failed: The TLS connection was non-properly terminated.` and the salvage push seconds later succeeded. `packages/runner/src/envelope.ts` reported phase DELIVER, `agentExited: true`; `packages/api/src/execution.ts envelopeExternalFailure` correctly said external (phase != EXECUTE), but `envelopeFailureClass` decides the class by text: no auth match, no typed transient marker (`packages/runner/src/network-retry.ts isTransientNetworkError` has no GnuTLS phrase, so the push was not retried either), no `TRANSIENT_NETWORK_PATTERNS` match (the list is the macOS-era LibreSSL/ECONNRESET vocabulary; the Linux runners' git links GnuTLS), so it fell through to TASK_FAILED, which `run-completion.ts` excludes from both refund (`refundable`) and retry (`failureIsRetryable`). Result: `Run 1 external failure was not eligible for a budget refund`, the finished work discarded, the step in REVIEW until an operator retried it. Prod DB shows 35 Runs with `gnutls_handshake` in failureReason in 7 days; every DELIVER-phase one is `task-failed`. The same shape recurs with each new toolchain or provider wording; the phrase list cannot be completed. The phase and agentExited facts already on the envelope are the durable signal.

Changes:
1. `execution.ts envelopeFailureClass`: for `envelope.phase !== "EXECUTE"` with `agentExited`, after the existing BUDGET_EXCEEDED, NO_CHANGES_PRODUCED, manifest-missing and auth (`DETERMINISTIC_ACCESS_PATTERNS`) checks, return TRANSIENT_PROVIDER instead of falling through to TOOL_FAILED/TASK_FAILED. The transient phrase list keeps deciding only the EXECUTE phase (the agent's own process) and the capped-refund evidence; the deterministic veto list is the only text that makes a plumbing-phase failure final.
2. `run-completion.ts`: a plumbing-phase transient failure is refundable and retryable under the existing caps (`EXTERNAL_FAILURE_REFUND_CAP`, `maxRunsPerTask`); no new counters.
3. `packages/runner/src/delivery.ts` / `network-retry.ts`: the branch-push retry loop retries any push failure that is not a deterministic refusal (invert the predicate: veto list decides, not the transient list), with the existing backoff and lease-bounded budget, so most transport blips never reach the API. When the loop is exhausted, the completion reports the delivery failure as today (Change 1 then classifies it).
4. `docs/operator-api.md` failure-class section: state the phase rule (EXECUTE = agent's failure, text-classified; other phases = runner's failure, transient unless deterministically refused) and that a retried DELIVER failure re-pushes the same commit.

Out of scope: adopting the salvage branch as the delivered head; changing the EXECUTE-phase classification or its phrase lists; agent-process crashes in EXECUTE (card cmtrad0i406tidbcnuzxtstqm covers the repair-Run case via remaining session budget); the refund cap value.

Constraints: the deterministic veto list stays short and is the only text consulted for plumbing phases; no new configuration; the runner's advisory `runnerClass` remains ignored except for the two classes honoured today.

Acceptance: an API unit test builds a DELIVER envelope with an unknown transport message (for example the GnuTLS text) and asserts TRANSIENT_PROVIDER, retryable, external; a second test with `authentication failed` in the same phase asserts AUTH_REQUIRED and no retry; a runner unit test drives the push retry loop with an unknown non-deterministic error and asserts it is retried up to the budget, and with `permission denied` asserts it is not; the completion dbtest asserts the DELIVER-transient Run is refunded and a retry Run is queued rather than the Task moving to REVIEW; the handbook snapshot test passes.
