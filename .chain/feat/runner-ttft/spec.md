Runner: every model turn records time-to-first-token and task detail shows it

Each run's diagnostics include time-to-first-token (TTFT) p50 and p90, measured by the runner at the provider boundary and carried on SessionEvent payloads that already exist.

Background: the platform deliberately does not persist streamed chunks. The PI adapter (packages/runner/src/adapters/pi.ts, providerEventPersistence) drops incremental chunk events after using them for liveness; the Claude adapter (packages/runner/src/adapters/claude.ts) launches `claude -p --output-format stream-json --verbose` without partial-message output, so no delta events arrive at all; the Codex adapter (packages/runner/src/adapters/codex.ts) sees item.started and item.completed. AdapterState in packages/runner/src/adapters/runtime.ts tracks lastProgressEventAt and inFlightTool for stall detection, and emitAdapterEvent sends parsed events with their payload to the SessionEvent sink, whose existing persistence path stores them. Because only complete messages are persisted, TTFT cannot be reconstructed from stored rows. The preceding chain "Web: Task detail shows per-run diagnostics" added packages/api/src/run-metrics.ts and a `metrics` object on every `runs[]` entry of GET /tasks/:taskId, rendered as a diagnostics block in apps/web/src/pages/TaskDetail.tsx.

Changes:
1. AdapterState gains per-turn timing: `turnRequestedAt` set when a model turn's input is complete (MODEL_STARTED for the first turn; the tool completion or user input that starts each later turn, defined per adapter in a comment in runtime.ts), and `firstChunkAt` set by the first streamed model-output chunk of that turn. Both are in-memory only.
2. When the adapter persists the turn's completion event (Claude: the `assistant` message event; Codex: the item.completed `agent_message`; PI: `message_end`), it adds a `ttftMs` field under a namespaced key `anneal` in that event's payload. The field is absent, not 0, when firstChunkAt was never observed for that turn. No new SessionEvent type is introduced and no additional row is persisted per turn.
3. The Claude adapter enables partial-message output and adds a persistence policy, shaped like PI's providerEventPersistence, that keeps partial `stream_event` rows out of PROVIDER_RAW and parsed persistence while still updating liveness and firstChunkAt. PI takes firstChunkAt from the first message chunk of the turn it already parses for liveness. Codex takes firstChunkAt from the earliest event the CLI exposes for the agent message (item.started, or a delta if the installed CLI emits one); the chosen source is recorded in the adapter comment.
4. run-metrics.ts adds `metrics.ttft` with `p50Ms`, `p90Ms` and `samples` computed from the persisted `anneal.ttftMs` values of that session's completion events; `ttft` is null when samples is 0, which is the case for every run recorded before this change is deployed.
5. The events query in GET /tasks/:taskId extends its type filter to the completion event types needed for ttft while still excluding PROVIDER_RAW and selecting only the fields it reads.
6. The TaskDetail diagnostics block shows TTFT p50 / p90 with the sample count, with i18n strings in en.ts and zh.ts. docs/operator-api.md documents `metrics.ttft`.

Out of scope: output-rate or phase metrics semantics; board cards; baselines; persisting chunk payloads; changing stall-timeout semantics or defaults; RunnerBackendState; the Sessions page; database schema or migrations.

Constraints: the number and types of SessionEvent rows persisted for a given provider transcript must be identical before and after this change; only the payload of existing completion events gains a field. Stall detection keeps its current behaviour and its existing tests. A missing first chunk yields an absent field, never a zero. Partial-message stdout from Claude must never reach persistence.

Acceptance: adapter tests for Claude, Codex and PI replay transcript fixtures and assert that the persisted completion events carry `anneal.ttftMs` with the expected value and that the histogram of persisted event types is unchanged versus the pre-change fixture expectations; a Claude test asserts that a transcript containing partial stream events persists no row for them; a test proves a turn with no observed chunk persists no `ttftMs`; run-metrics tests prove p50/p90/samples and null on zero samples; a route test asserts `metrics.ttft` is present; web tests render the TTFT row and the null case; `npm run lint`, `npm run typecheck`, and `npm run test` for @anneal/runner, @anneal/api and @anneal/web are green (with RUNNER_WORKSPACE_ROOT set to a fresh temporary directory for runner tests); docs/operator-api.md documents `metrics.ttft`.
