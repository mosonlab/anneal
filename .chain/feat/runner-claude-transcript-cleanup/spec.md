Runner: a Claude Run's transcript is removed with its workspace

After a Run's workspace is removed, the Claude CLI transcript that Run wrote under the runner account's home is removed as well, so finished Runs leave no transcript files behind.

Background: The Claude adapter (`packages/runner/src/adapters/claude.ts`, `claudeArgs`) deliberately launches the CLI without a `CLAUDE_CONFIG_DIR` or `HOME` override, because authentication is the CLI's Keychain flow tied to the runner account's home (`workspaceEnvironment` in `adapters/environment.ts` passes `HOME: config.home`). The Claude CLI therefore writes each session's transcript to `<config.home>/.claude/projects/<mangled cwd>/<sessionId>.jsonl`, where `<mangled cwd>` is the workspace path with every character outside `[A-Za-z0-9]` replaced by `-` (for example workspace `/Users/leohe/.agentos/production/agentos/shared/runs/<runId>` becomes directory `-Users-leohe--agentos-production-agentos-shared-runs-<runId>`), and `<sessionId>` is the `session_id` the adapter records as `providerConversationId`. Workspace disposal (`disposeWorkspace` in `dispose-workspace.ts`) ends with `cleanupWorkspace` (`workspace.ts`), which removes only the workspace directory. Nothing removes the transcript directory, so on the Mac runners (six runner daemons sharing `HOME=/Users/leohe`) every finished Claude Run leaves one directory behind: 326 directories / 207 MB accumulated by 2026-09-08 for the current workspace root alone, plus 300 more under two retired roots. Codex and PI do not leak: both relocate `HOME` to the session scratch config root, which is removed with the session.

The transcript must survive as long as the Run can still be resumed. Provider relaunch inside a Run (`runner.ts`, `provider-relaunch.ts`) re-launches the CLI with `--resume <providerConversationId>`, which reads that same transcript; a `retain` disposal keeps the workspace for diagnosis or resume. So the transcript's lifetime must equal the workspace's lifetime, not the CLI process's lifetime.

Changes:
1. `disposeWorkspace` removes the Claude transcript directory for the workspace it just removed. The directory path is derived from the workspace path with the CLI's mangling rule stated in Background, rooted at `<config.home>/.claude/projects`. Removal happens only after `cleanupWorkspace` has succeeded, and covers both disposal identities (`source: "runner"` from `runner.ts` and `source: "reclaim"` from `reclaim.ts`) because both call `disposeWorkspace`.
2. A `retain` disposal (cleanupStatus `RETAINED`) leaves the transcript directory in place, and a disposal that returns `FAILED` before or during `cleanupWorkspace` leaves it in place.
3. A missing transcript directory is the normal outcome for Codex and PI Runs and for Claude Runs that never reached the CLI; it is not an error and produces no audit line.
4. The derived path is guarded: removal proceeds only when the resolved path is strictly inside `<config.home>/.claude/projects` and is not that root itself; otherwise the guard throws, mirroring the existing `cleanupWorkspace` guard.
5. A transcript removal failure (other than the directory being absent) does not change the returned `cleanupStatus`, because the workspace itself is already gone; it emits a `workspace-disposal` audit line with event `transcript-remove-failed` carrying the run id, the path, and the error message, through the existing `audit` helper in `dispose-workspace.ts`.
6. Tests in `dispose-workspace.test.ts` cover: a transcript directory under a temporary `home` is removed on a `SUCCEEDED` disposal; it is kept on a `RETAINED` disposal; an absent directory yields `SUCCEEDED` with no audit line; a path escaping the projects root is refused.

Out of scope: setting `CLAUDE_CONFIG_DIR` or relocating `HOME` for Claude sessions (authentication and settings discovery depend on the current arrangement); any change to Codex or PI scratch handling (verify they already remove their transcripts with the scratch root, do not add code); removing transcripts at CLI exit or at session end; cleaning up transcript directories that already exist on hosts (operator work, done by hand on 2026-09-08); the `~/.claude/debug` or other CLI state directories; any change to `cleanupWorkspace`, `provider-relaunch.ts`, `reclaim.ts`, or the `CleanupStatus` vocabulary; documentation outside the runner package.

Constraints: The transcript is removed only in the same code path and after the same preconditions as the workspace directory; no new configuration flag, environment variable, or `RunnerConfig` field. Path derivation uses `config.home`, never `process.env.HOME` or `os.homedir()`. Tests pin `home` to a fresh temporary directory and set `RUNNER_WORKSPACE_ROOT` to a temporary directory per repository rules; no test touches the real `~/.claude`.

Acceptance:
- `npm run test -w packages/runner` is green, including the new `dispose-workspace.test.ts` cases named in Change 6.
- `npm run typecheck -w packages/runner` and `npm run lint -w packages/runner` are green.
- In the `SUCCEEDED` test, after disposal the directory `<home>/.claude/projects/<mangled workspace path>` does not exist and `<home>/.claude/projects` still exists.
- In the `RETAINED` test, the transcript directory still exists after disposal.
- In the absent-directory test, disposal returns `cleanupStatus: "SUCCEEDED"` and no `workspace-disposal` audit line with event `transcript-remove-failed` is written.
- `git grep -n "CLAUDE_CONFIG_DIR" packages/runner/src/adapters/claude.ts` shows the same lines as before the change (the adapter's environment is untouched), and `git diff --stat origin/main` lists no files outside `packages/runner/src/dispose-workspace.ts` and `packages/runner/src/dispose-workspace.test.ts`.
